# Levels

Each level is a folder of plain data files. `npm run build` compiles them into the game: the collision map becomes `level_mc`, the art becomes `background_mc`, each placement list becomes a clip on `screen_mc`, and every level gets a briefing frame and a game frame on `screen_mc`. `tools/levels/levels.mjs` does this, called from `tools/flash-source/build.mjs`.

The folder is named like the level's entry in the `levels` array in `as2/functionsLevel.as` (for example `03_Bridge`), and folders are numbered from `00` without gaps. To add a level, add its folder and make sure its entry in that array isn't commented out.

| File | What |
| --- | --- |
| `level.json` | Level settings, all optional. `art` (`{"kit": "bridge", "seed": 2012}`) means the background is generated by the art pipeline (see Art below); levels without it keep their original art. The minimum loadout and timer will go here too |
| `collision.png` | The collision map, pixel for pixel what the game hit-tests: black is wall, `#999999` is impassable but can be shot over (chasms), white is open floor. Its size is the level's size |
| `background.png` | The level art, the same size as the collision map |
| `briefing.json` | The briefing screen, as `{"changes": [...]}` in the timeline format of [source/README.md](../source/README.md) |
| `boxes.json` | Boxes, placed inside `boxes_mc` |
| `powerups.json` | Pickups and message beacons, placed inside `powerups_mc` |
| `enemies.json` | Enemies, placed inside `enemies_mc` |
| `doors.json` | Doors and gates, placed on `screen_mc` under the level |
| `features.json` | Everything else on `screen_mc`: `entrance_mc`, `exit_mc` |
| `pathNodes.json` | Pathfinding nodes (`game objects/node`, `as2/pathNode.as`), placed on `screen_mc` right after the features |
| `vision.json` | Vision zones, the clips inside `vision_mc`, which the build places on `screen_mc` (see below) |
| `decor.json` | Decor placements the art bake paints into `background.png`, one per line: `{"sprite": "lights/12.png", "x", "y", "scale", "rotation" (degrees counter-clockwise), "effect": "paint"/"shadow"/"glow", "strength"}`, sprites from `tools/art/parts/decor/`. Written by `bake.py place`, editable in the level editor. The game doesn't read it |

A missing placement file means an empty list.

## Placements

Every placement file is a list of instances, drawn in list order (later ones on top):

```json
[
  {"symbol": "game objects/box", "x": 722, "y": 62},
  {"symbol": "enemy assets/enemy wolfgun", "x": 246.95, "y": 475.75, "props": {"health": 200, "powerupDrop": {"type": "primary", "item": "Plasma", "quantity": 10}}},
  {"symbol": "game objects/door", "x": 1009.9, "y": 50.4, "props": {"id": "door2"}}
]
```

- `symbol` is a library name from `source/library`.
- `x`, `y`, `scale`, `matrix` (for rotation), `name`, `color`, `filters` and `blend` work as in the timeline format.
- `props` are the instance's variables, set when it loads (they become its `onClipEvent (load)` script). Values are numbers, strings, `true`/`false`, lists and objects, and `{"$ref": "a2"}` for the sibling clip named `a2` (path nodes list their linked nodes this way: `"connections": [{"$ref": "a2"}, {"$ref": "a4"}]`).
- `{"$trigger": "door2:open"}` (or a list of names) is a function that sends those triggers, for a pickup's `onPickup` or a box's or enemy's `onDie`: `"props": {"onPickup": {"$trigger": "door2:open"}}`.
- `script` is used instead of `props` when the load code is more than plain variables, such as the Bridge's battery computers, whose `onDie` also throws shrapnel. It's kept as written.

## Triggers

Triggers are names sent with `trigger("name")` to every clip that registered for them. A door with `"id": "door2"` listens for `door2:open` and `door2:close`. An area that sends a trigger when the player walks into it is a trigger pad: an invisible pickup with `"type": "trigger", "item": "door2:open"`, sized with `scale`. Boxes and enemies send one when destroyed with an `onDie` `$trigger` handler as above. A load script can also call `trigger()`.

## Messages

A pickup or message beacon with `alertMessage` shows that message while the player is over it. After the player leaves, it stays up for 4 seconds (`alertLinger` sets another time in seconds), and a different message replaces it straight away.

## Path nodes

A node with no `connections` links itself, when the level starts, to every other node of the same colour that it has line of sight to (`as2/pathNode.as`). The colour (`color.add`) is the node's path group, and an enemy follows the group of the node nearest to it unless it sets `pathID`. To pin a node's links by hand, give it `"connections": [{"$ref": "a2"}, ...]` naming other nodes.

## Vision zones

An enemy attacks when it and the player are in the same zone and it can see the player. An enemy that isn't in any zone, or has `autoVision`, makes its own zone from 90 rays when the level starts, so a level works without any zones. Each zone in `vision.json` is `{x, y, scale|matrix, d}` with `d` a path (`M`, `L`, `Q`, `Z`, absolute) in the zone's own coordinates, or `{x, y, points: [[x, y], ...]}` for a plain polygon. Zones have no stored colour: the game only hit-tests their shapes, and the build draws zone k in its own hue (`zoneColour(k)` in `tools/levels/compile.mjs`) so every zone in a level looks different in the editor and explorer.

## Levels 00 to 03

These came out of the original `screen_mc` and `level assets/*` symbols unchanged. Their collision maps and backgrounds are the bitmaps the original game used (the Bridge's collision map was rendered from its vector shape exactly as the game rasterised it). The Bridge's background is baked by `tools/art/bake.py` (see Art below).

## Level editor

Press backtick (`` ` ``) in the game, or open the page with `?edit` (`?edit=3` for the Bridge). The game pauses and the editor shows the level as it starts, drawn by the game itself, with a panel on the right. Backtick again (or **Play**) goes back to the game, restarted from the edited level.

- **Layers:** each row has an eye (show or hide; number keys 1 to 9 do the same for background art, collision, vision zones, enemies, boxes, pickups, doors, entrance/exit/player and path nodes) and a lock (a locked layer can't be selected or edited). Picking a tool never changes the layers, and the layers never change the tool. Clicking a layer's name points the tools that can work on it there: Place then adds to that layer (enemies, boxes, decor and so on), and Polygon draws collision or a vision zone. The rows the current tool works on have a green edge (also listed as "Works on" under the tools), and rows holding something selected are lit cyan with a count. A clicked layer name is underlined, and the tools that work on it get a green edge.
- **Snapping:** nothing snaps unless Shift is held. With Shift, moves, placements, rectangles and zone corners snap to the grid (the size is under the tools), and Polygon snaps its first corner to the grid and each next side to the angle step. The grid shows while Shift is down.
- **Art preview (A):** fills the collision map with the Bridge kit's floor, wall and chasm textures (`tools/art/parts`), with rough wall sides, bevels and chasm lips, and redraws it as you edit collision. It's a guide, not the bake.
- **Select (V):** works on every shown, unlocked layer at once (where things overlap, the smallest is picked; vision zones only when nothing else is there): click to select, Shift+click to add or remove more, from any layer, drag to move (everything selected moves together), arrow keys nudge 1 px (Shift: 10 px; presses in a row are one undo step), R rotates by 15°, Delete removes, Ctrl+D duplicates. The selection is a solid cyan box with corner handles (white on the one clicked last); other outlines are thin and dashed. With several selected, the panel turns and scales the group about its centre, aligns them in a row (same y) or a column (same x), and spaces three or more evenly across or down between the outermost two. Number fields apply as you type or step them, one undo step per edit. The panel edits position, rotation, scale, name and the load variables (`props`) as JSON. Instances with a load `script` show it read-only.
- **Place (P):** pick the layer in the tabs ("Place on"), then a symbol from the palette (everything already used in a level for that layer, plus the recovered enemies, plus a ready-made trigger pad), then click. New instances copy the variables of an existing one of the same symbol; doors get the next free `id`.
- **Hidden things:** anything the game doesn't show (trigger pads, alpha-0 areas, pickups with nothing to draw, enemies hidden at the start) is outlined and named when its layer is on, so it can be seen and selected.
- **Triggers (T):** an overlay, independent of the layers: every sender is labelled on the map with what it sends, and dashed lines show which door each one opens (green) or closes (red). The **Triggers** list in the panel shows every door and sender in the level; click one to select it. A selected pickup, box or enemy has a field for the triggers it sends when picked up, destroyed or killed, and a trigger pad for the one it sends; both suggest the level's door triggers.
- **Path nodes:** their own layer (Place on "Path nodes" adds one). A new node joins the selected node's path group (or the level's first) and links itself by line of sight; these links show dashed, computed the same way as the game. A selected node's panel sets the group colour and lists its links, each with an **unlink** button. **Path links (N):** click a node, then another, to add the link (or remove it if they were linked). A node whose links you change keeps them pinned (solid); **Back to automatic** in the panel unpins them.
- **Vision zones:** show the Vision layer (3). Select moves, rotates and deletes zones and drags a polygon zone's corners; zones with curves get an **Edit corners** button that turns them into a polygon. Polygon (G) with "Draws: a vision zone" draws a zone, and Auto zone (Z) makes one from the spot you click, with the same rays the game uses.
- **Collision:** Rectangle (B) drags a box; Polygon (G) closes on the first corner or Enter; Pencil (D) and Eraser (E) paint single pixels or bigger brushes (`[` `]`); Fill (F) flood-fills. W, C and O pick wall, chasm or open floor. Everything is drawn aliased in exactly the three collision colours. Scroll to zoom (pixel grid from 1200%), drag with Space, the right or the middle button to pan, 0 to fit.
- **Decor (K):** show the Decor layer to see `decor.json` drawn over the art (the background still shows the last bake). Select moves one, R turns it, Delete removes it, and the panel sets its sprite, size, rotation and bake effect. Place (P) on "Decor" shows the decor sprites by category; a new one takes its category's usual size and effect.
- **Undo/redo:** Ctrl+Z, Ctrl+Shift+Z.
- **Balance:** enemy, box and pickup counts, health on the map and ammo per weapon, counting box and enemy drops at their probability.

**Saving.** Run `npm run edit` and open http://localhost:8123/?edit: Save (Ctrl+S) writes only the changed files into `levels/<NN_name>/` and rebuilds. Anywhere else (for example the GitHub Pages site) Save downloads the changed files instead. After changing the collision map, press Bake art (see Art), which the editor reminds you about. A badge at the top of the panel shows the server status, re-checked every few seconds: green when `npm run edit` is connected, pulsing yellow while it saves or builds, red if the last build failed, and hollow when there is no server (Save downloads).

The editor recompiles levels in the browser with the same code as the build (`tools/levels/compile.mjs`). Load variables apply directly; instance scripts reuse the build's compiled code, so a changed `script` needs `npm run build`.

## Art

A level with `art` in its `level.json` gets its `background.png` generated from its collision map by `tools/art/bake.py` (Python with numpy, scipy and Pillow: `python -m pip install numpy scipy pillow`), in two steps:

1. **place**: lays out decor from the seed (floor paint, rails on chasm lips, greebles, vents, wall marks, lights) and writes `decor.json`, replacing what was there.
2. **bake**: draws the floor, chasm and walls of the kit from `collision.png`, then each `decor.json` placement with its effect, and writes `background.png`.

`python tools/art/bake.py 03_Bridge bake` (or `place`, or `all`; `--seed N` overrides the seed; `--only lights,rails` re-places just those types and keeps the rest of `decor.json`). Rails along one continuous chasm edge all use the same sprite.

**Options.** `tools/art/options.json` lists the bake's options with their defaults: wall edges (corner rounding, edge softness, sharpen), wall sides (built like the originals: the wall art copied, darkened and scaled down a little toward a camera point, several times over; copies, scale per copy, brightness, fade, camera point), chasm stripes (width, period, angle, two colours, opacity, or a texture from `tools/art/parts`), lights (each lit piece casts a pool of its own colour, blended as light, plus a bloom), and for Re-place: greebles (count, size, overhang) and floor panels (count, sizes, corner lights, emboss depth).

**Decor is only drawn.** It is baked into `background.png` and never changes `collision.png`, even where a greeble sticks out past a wall edge. **Floor panels** (`tools/art/parts/decor/panels`, made by `tools/art/make_panels.py`) are height maps with the `emboss` effect; the level's entrance always gets one, and some get a light in each corner (`"of": "panels"`, re-placed with them). A level overrides them in `level.json`, for example `"art": {"kit": "bridge", "seed": 2012, "sides": {"steps": 14}}`. The editor's Art pipeline section has a field for each (changed ones in yellow) and checkboxes for which decor types Re-place lays out again.

 In the editor, with `npm run edit`, the **Art pipeline** section runs them on your machine: **Bake art** saves, bakes and rebuilds, so walls you drew and decor you moved show up in the art; **Re-place decor + bake** lays out fresh decor from the seed (🎲 picks a new one) and bakes. Either way the editor then reloads with the new art, on the same level and view. A level without `art` offers a button to start generating its art (the old background stays in git).
